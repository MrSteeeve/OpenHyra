# P2-M0a: 研究工作进程与部署边界

P1 封板基准：Stochopia `4b840e34d84308283d920aee7a5a6a071dde9c34`，
OpenHyra `93e43f28354126e150adfb96e7da99f21f05025f`，两仓均为
`p1-szse-final`。历史冻结证据、候选源码和原始测量不作修改；复现 P1
正式实验仍以原标签的代码和冻结清单为准。

## 职责

- 本仓库运行受信任、非公网输入的研究算子。Python 层使用标准库工作进程、
  墙钟计时、进程组回收、临时目录和环境白名单。它不是文件系统或网络
  权限隔离。外层云 VM/容器负责部署层的权限、资源、数据及凭证边界。
- `sandbox.py` 是兼容入口；`worker_subprocess.py` 是共享执行器；
  `sandbox_artifacts.py` 保留历史科研表单、结构化评分及哈希封存契约。
  临时工作文件自动清理，日志从临时文件读取末尾 64 KiB。旧评估器如需
  完整的 JSON 结果可以显式选用其原有输出读取上限。
- Gate 只写候选源码，使用共享的实际项目源码和标准 importlib；市场评估
  同样不为每次运行复制实现文件。PyTorch 线程数固定，关闭 CUDA TF32。
  运行数据划分、参数/状态维度、因果前缀探测（atol=1e-5）、step/sequence
  等价、掩码、有限损失与梯度检查保持不变。因果探测是具体合成探针上的
  验证，不等同于对任意程序的形式证明。
- 设备缓存区分 CPU 和 CUDA，CUDA 使用规范设备标识及硬件指纹。原 P1 CPU
  缓存只可用于相同 CPU 训练协议；不会跨 CPU/CUDA 共享。当前正式 P1 模型
  默认 CPU，未来 P2 正式实验须在实验清单中登记设备与后端。当前本机无
  CUDA 硬件，设备路由和缓存单测不等于 GPU 实机验证。

## 真实候选等价性冒烟
