# 从 Ridge 起点到不同求解方法：机制探索试验

本报告区分历史诊断、结构干预、可执行跃迁和性能。研究目标是观察并解释至少一次方法迁移，不声称发现人类未知算法，也不以更换模型名称作为成功标准。

## 历史诊断：首先修正问题的范围

核查了原始实验的 24 次生成尝试、补充实验的 12 次预设尝试，以及 52 份调用记录。补充实验的基础设施恢复不当成额外独立尝试；原失败和恢复记录都有链接。逐条表格见 `../artifacts/innovation-transition-audit/README.md`，输入/输出索引见 `call_index.json`，源文件哈希、计划、状态及实现核查见 `trajectories.json`。

1. **整个历史并非始终只有 Ridge。** 原始 Context s29/sol_0003 已从 Ridge 父程序生成并成功评价 kNN 直接停时程序；原始直接生成 s17/sol_0003 是 bootstrap 稳定化的 payoff 阈值搜索。两者代码的实际计算路径与 Ridge 不同。
2. **最近补充实验发生了规划收缩。** 四次成功整程序重写都在 Context 阶段选择 Ridge/LSMC；另外两次 Context 超时。清空代码发生在选定机制之后，因此不能靠重写操作名称消除规划依赖。
3. **想到了不同方法、但没生成成功，是另一种失败。** 原始 Context s41/sol_0003 提出树方法，但 Proposal 超时；不能称为没有创新意愿，也不能把残留源码计为成功。
4. **保持线性表示不等于只调参。** 补充 s29 结构化局部重写提出并实现直接优化期望停时收益，但保持线性预测器与 Ridge 回退。缺少最终分支追踪，不能断言最终部署的就是优化后的系数。
5. **近期补充试验不能代表完整主 Harness。** 它固定父程序、固定历史、每次只生成一个计划，没有消费本轮新增结果；局部重写还保留预测器格式。完整原始流程和简化补充流程必须分开。

候选原因包括：规划阶段父源码锚定；单方案选择与小样本/短预算促使低方差保守路线；局部预测接口限制；生成超时；只观察赢家造成探索遗漏；置信 gap 的排序与收益点估计并不完全一致。前述设置和轨迹有证据，但单一因素的因果效应尚未识别。模型输出的理由是其声明的理由，不能直接视为真实因果解释。

## 外部方法如何进入设计

- [Stanford analogical reasoning](https://arxiv.org/html/2605.11258v1)：把问题关系、迁移方法与不对应之处显式化。本次落实为计划中的 analogy.mapping/non_correspondence 和预测/反驳条件，不指定目的模型族。
- [DreamCoder](https://www.neurosymbolic.org/papers/EllisWNSMHCST21.pdf)：启发我们把可重组的机制与程序实现分开，并保留失败和未胜出的经验。本次只是显式机制表述和实验历史；**没有实现程序抽象学习或贝叶斯先验训练**。
- [DiscoRL](https://www.nature.com/articles/s41586-025-09761-x)：启发我们区分候选求解算法与研究策略。这里改变并检验研究策略；**没有元梯度训练，没有更新 Context 模型权重，也没有建立跨任务迁移证据**。

## 已实现的新结构

`research_planning.py` 提供公开证据投影、机制规划提示和有证据引用检查的解析器。`experiments/run_innovation_transition.py` 运行真实 Context/Proposal，并使用原有独立 evaluator 和 Seatbelt 执行。

```mermaid
flowchart LR
    A[固定 Ridge 起点与公开评价] --> B[问题关系与竞争解释]
    B --> C[三个候选机制与适用边界]
    C --> D[Context 选择一个方案]
    D --> E[空白 fit/predict 实现]
    E --> F[独立训练与评价]
    F --> G[保存失败和未胜出候选]
    G --> B
```

两组使用同一模型、完整任务接口、三个方案的输出格式、相同调用上限和训练/评价预算：

- `parent_visible`：规划时展示 Ridge 源码，要求提出最有希望的改进。
- `mechanism_first`：规划时不展示父实现，要求从问题关系提出一个局部方案和两个改变机制的方案，选一个可行的非局部方案。要求明确类比、不对应关系和可检验预期。没有 MLP/Transformer/树/kNN 的目的族菜单。

两组 Proposal 都走现有 `whole_program_restart` 路径；这里只研究规划源代码暴露，不声称端到端对父源完全不可见。第二轮消费本组第一轮结果，包括失败。父程序固定为 Ridge，探索结果独立保留；本试验不实现动态性能父选择。所有公开生成完成后，才评价独立面板，独立结果不回流。

这是一个**组合干预的机制可行性试验**，不是单因素消融。明确要求非局部探索也意味着不能将结果称为完全自发的创新。一个独立种子、每组两轮，只能支持存在性案例；两个候选不是两次独立重复。

## 验收标准

- 提案：是否提出不同表示、训练目标或求解机制。
- 实现：从训练到序列化到预测的计算路径是否真实改变，不能只看注释和模型自报标签。
- 执行：真实 fit/predict 与评价是否成功；新结构必须进入实际预测。
- 行为：固定独立查询上是否产生不同决策，区别于仅改文件名。
- 性能：另报收益、gap 和不确定性。性能不佳不否认方法迁移，迁移本身也不证明性能提高。

## 运行与证据

试验目录为 `../artifacts/innovation-transition-s73/`。`protocol.json` 在调用前冻结模型、预算、请求及代码哈希。`frozen_runtime/` 保存实际执行版本；每个 arm/round 保存输入、输出、计划、packet、程序和公开结果。`public_complete.json` 先于所有 private 文件产生。所有失败保留，不重抽计划，不人工替换候选实现。

独立机制检查目录为 `../artifacts/innovation-transition-inspection/`。它重新在原有训练沙箱中训练候选和 Ridge，保存模型并在同一批状态上查询。该诊断不是额外性能测试或独立搜索重复。

运行新的独立试验：

```sh
python3 experiments/run_innovation_transition.py --output /absolute/new/output --seed 73
```

每次输出目录必须不存在，防止静默覆盖或重新抽样。相同随机种子只约束数值训练/评价，不保证 API/CLI 模型生成相同文本。

结果与逐项验收见 `../artifacts/innovation-transition-s73/RESULTS.md`（实验结束后生成）。

## 如何解释本试验，而不是包装成创新成功

“创新”在这里分为四个不同对象：候选表示、训练目标、求解过程、研究策略。一次跨表示变化只支持对应维度的改变。Ridge→树直接决策同时改变表示、训练目标和输出接口；Ridge→局部核回归改变表示与拟合/预测机制，但仍沿用逆向递推。因此二者都不同于只调 Ridge 正则化，却都不是人类未知算法。

本次真正值得后续检验的假设是：**探索收缩可能来自研究组织方式，而非候选编程语言的可表达能力。** 原始流程已出现 kNN，最近简化流程四次成功整程序重写却都回到 Ridge；新机制流程又生成了不同方法。这是一个可重复实验的线索，但历史流程、任务面板、模型调用时机和指令有差异，不能把历史对比写成因果估计。

下一阶段若做 workshop 归因实验，应固定其余设置，分别测试：规划是否暴露父源码、是否要求候选机制多样性、是否消费新增反馈。应使用新的独立运行确认，保留所有失败；不要只从成功的候选数计算稳定性。当前组合试验不能替代这些消融。

### 已发现的候选实现边界

- 第一轮浅树确实以 advantage 的符号作为标签、绝对值作为错误代价，并在预测时遍历实际拟合树。交叉验证用于选择树参数，但递推现金流仍由全样本树更新，不能把它称为已经严格完成全链路交叉拟合的停时估计。候选没有被人工修补。
- 第二轮核方法在实际预测中使用邻居样本、距离和带宽。`_ridge_oof` 仅产生训练诊断，未用于切换部署方法。所谓 prior 实际是邻域均值收缩，并非一般全局先验。其训练期置换诊断不等于独立的机制证据。
- 对候选的正确表述是“实际生成并执行了该机制”，不是其所有理论解释或统计断言均成立。训练代码通过接口和数值检查也不证明学术新颖性。
