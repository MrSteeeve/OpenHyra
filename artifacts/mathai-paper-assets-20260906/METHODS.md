# 指标、实验设计与论文使用说明

本包的研究对象是百慕大期权的因果停时算法。候选 Python 程序从训练样本构造策略，在每个允许行权时点依据当前和已观测状态决定行权或继续。回归、MLP 和规则阈值都是策略构造方式；模型内部使用预测不改变最终的最优停时目标。

## 理论量与样本估计量

令折现收益过程为 Z，合法停时集合为 T。定义 V* = sup E[Z_tau]，L_pi = E[Z_tau_pi]。对合法策略和有效对偶上界 U，有：

    L_pi <= V* <= U
    0 <= V* - L_pi <= U - L_pi.

因此，小 gap 给出较紧的策略次优程度上界。若对所有候选保持同一个 U，降低真实 gap 等价于提高策略期望收益。若 U 同时改变，gap 降低也可能来自上界收紧；不能自动推断策略改善。这里的 Python 策略共享 evaluator-owned Ridge LSMC 对偶构造。

这部分依据已有对偶理论，不作为本项目的新定理。可引用 [Rogers (2002), Monte Carlo valuation of American options](https://onlinelibrary.wiley.com/doi/10.1111/1467-9965.02010) 和 [Haugh & Kogan (2004), Pricing American Options: A Duality Approach](https://pubsonline.informs.org/doi/10.1287/opre.1030.0070)。百慕大期权的 primal–dual 模拟与区间构造可参照 [Andersen & Broadie (2004)](https://pubsonline.informs.org/doi/10.1287/mnsc.1040.0258)。书目信息于 2026-09-06 核对出版社页面。

表中的 L 与 U 是独立路径上的蒙特卡洛估计，严格记号应写成 L_hat 与 U_hat。每个实例 i 的实际评价量为：

    raw_gap_i = U_hat_i - L_hat_i
    confidence_gap_i = raw_gap_i + z * (SE(U_hat_i) + SE(L_hat_i))
    normalized_confidence_gap_i = confidence_gap_i / K_i
    z = 1.9599639845400536
    score = mean(normalized_confidence_gap) + 0.25 * quantile_0.9(normalized_confidence_gap).

z 对应两个单侧区间的 Bonferroni 分配，使用正态近似。它不等于任意有限样本下的精确覆盖保证。主表的 gap score 包含不确定性余量和尾部分位数项，不是简单的 U-L，也不是期权价格百分比误差。负的原始样本 gap 没有被裁剪。每个实例的完整原始量和标准误均可追溯。

在数值评价中即使共同 U 不变，标准误和分位数项仍会影响 gap score 的排序。因此，本文同时报告策略收益、原始 gap 和置信 gap。宽 gap 也可能主要反映共同上界不够紧。

## 数据分层

| 层次 | 样本与用途 | 可否用于选择 |
|---|---|---|
| 原始公开搜索 | 3 seeds，每条流程两轮、每轮两个尝试；收益改善 LCB | 原始实验用于选候选 |
| 原始隐藏审计补全 | 原始隐藏请求重评七类参考算法 | 回顾性比较，不能称新独立测试 |
| 新校准面板 | seed 330017 / 330029 / 330041；每 seed 两实例，256 训练、1024 定价、128 outer × 8 inner | 新反馈对照使用 |

最终测试预算比校准更大，程序可以在该预算下重新 fit；候选代码、选择和规则在之前已冻结。不同 seed 面板包含不同合约参数；本实验只有三个独立 seed 区组，不能把 12 个合约或大量路径当成大量独立搜索重复。跨 seed SD 是描述性变化范围，图中的路径级误差条是条件蒙特卡洛误差。

## 对照设计

原始 Context→Proposal 与直接生成流程具有不同的 Context 开销和父程序选择方式，不能视为严格等计算量的架构消融。其结果、24 个生成尝试、5 次超时和实际成本都保留。

本轮新实验控制父程序、同一历史候选集合、模型 gpt-5.6-sol、两个预设操作符、训练预算以及模型调用时间上限。结构化组获得分数、逐实例上下界、不确定性和明确标注的历史行为/机制记录；分数组获得相同候选 ID、源码哈希、状态和标量 gap。每个计划最多一个 Context 调用（120 秒）与一个 Proposal 调用（180 秒）。调用上限相同，不声称实际 token 数或运行时间完全一致。

三个 seed × 两个操作符形成六对尝试；操作符共用同一 seed 的父程序与历史，所以独立区组仍为三个。每个操作符只从同一固定父程序产生一次提案。这是固定历史的反馈信息消融，不能称作新增多轮递归搜索，也不能单独归因于 Context Agent 或 Experience Bank 的某一个内部部件。

首次运行在复制只读父程序时出现工作目录准备错误，十个已成功的 Context 计划尚未触发 Proposal，两个 Context 超时。恢复版本在所有后续 Proposal 调用之前冻结说明，创建字节相同的可编辑父程序副本，沿用已有计划，保留超时，不重试模型。原始记录与成本完整保留。恢复没有修改冻结验证器或旧结果；详见 protocol.json 与 recovery_amendment.json。

## 表图解释

- 主表包含七类参考算法、原始两组最佳已生成算法、保留初始参考的原始两组 incumbent、按校准 gap 选出的新两组 incumbent。相同源码被多个选择规则选中时会出现在多行；这些行不是新的独立评估。
- 新反馈图左侧报告两个预设提案的平均校准 gap 改变量，失败提案保留父程序并计为零；正常生成但更差的提案可以为负。右侧报告允许保留父程序的校准选中 incumbent 在独立测试上的变化。
- 原始搜索图下方是对当时收益分数选中的同一 incumbent 做事后 gap 重评；不是原始实验实际使用 gap 反馈的证据。
- 停时分布图来自原始冻结候选的实际行为，未根据最终测试结果挑选案例。它展示行权时间分布，不推断机制的因果效果。
- 成本图中的分钟是模型调用时间之和，含超时；不等于并行运行的墙钟时间。token 缺失项未补估，已报告 token 总和是可见记录的下界。

## 重建与复核

scripts/build_assets.py 使用冻结的 inputs、raw 和候选记录重新生成图表、CSV、Excel 与图册，不触发模型实验。scripts/verify_assets.py 校验计分公式、表格汇总、配对条件、源码与选择一致性，并重开 Excel/PDF。

frozen_runtime/ 保存原始数值评价代码。生成过程的原始驱动脚本及恢复脚本保留原项目路径语义与哈希，作为执行记录；请勿编辑其内容后将新运行冒充原运行。需要发起新的科学实验时，应使用新目录和新协议。
